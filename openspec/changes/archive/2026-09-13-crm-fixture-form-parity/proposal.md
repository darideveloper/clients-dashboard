## Why

The CRM models manage sales generated by the live buy form (`Ourlens US Order Form V2`, Formidable `form_id=20` at ourlivesapp.com/sales/). Every static dropdown on that form must already exist as reference rows in the codebase, otherwise order intake (admin select, validation, future import) points at empty tables. Five of six static lists are preloaded; `Product` (Micro/Regional/Enterprise Pilot × currency) is missing entirely.

## What Changes

- Add base fixture `ourlives/fixtures/ourlives/Product.json` with 12 rows: 3 tiers (Micro, Regional, Enterprise Pilot) × 4 pilot currencies (USD, CAD, GBP, ZAR), explicit PKs, FKs to the existing `Currency` PKs (USD=1, GBP=4, CAD=8, ZAR=12), all `active` true. Zero loader edits (auto-discovered by `base_loaddata`).
- Keep all 5 existing fixtures byte-identical: `Country.json` (249 ISO-3166), `Currency.json` (12), `ContactType.json` (4), `CodeType.json` (2), `OrderType.json` (4).
- Explicitly add nothing for: `Rep` (admin-created by design), `Project`/`Organization`/`Contact`/`OrganizationAddress`/`Order`/`OrderItem` (transactional per-sale), `InvitationCode` (token-pool constrained + CSV import path), `AppSettings` (singleton), `StripeEvent` (audit log).
- Document two form quirks as non-fixture issues (no code change here): EUR pilot path shows no product block; form country labels (251, with `Kosovo`, `Holy See`+`Vatican City`, `East Timor`+`Timor-Leste` duplicates and colloquial names like `Brunei`, `Swaziland`) need label→ISO normalization at import time, not fixture changes. Form has no Company Name input (address only) — CRM import must decide how `Organization.name` is sourced.

## Capabilities

### New Capabilities

- `product-fixture`: base `Product` catalog preloaded via `base_loaddata` (12 rows, explicit PKs, idempotent, unblocks pilot `OrderItem` creation).

### Modified Capabilities

- None. `crm-phase1-lookups`, `currency-fixture`, `crm-orders`, `fixture-system` requirements are unchanged (counts and PK schemes stay pinned).

## Impact

- `ourlives/fixtures/ourlives/Product.json` (new file only); `base_loaddata` picks it up with no loader, `start.sh`, or settings change.
- Tests: extend `Phase1FixturesTests`/`CurrencyFixtureTests`-style coverage for 12 products + idempotency (existing tests pin 249/4/2/4/12 — they keep passing unchanged).
- Blocked input: canonical `unit_price` per tier/currency is nowhere in the repo (form takes the amount per order; `db.sqlite3` predates CRM tables; page shows no catalog prices). Prices ship as TBD placeholders unless the sales team supplies them before implementation.
